## About BuildDock

BuildDock is a specialist freelance delivery team built by 3 senior developers
who work together as a unit on product builds. We take on select client projects
end to end - from architecture to deployment to post-launch support.

**How we work:**
- The 3 core developers handle everything: design, build, review, client calls, and deployment
- We use modern AI-assisted development tools to move faster and deliver more in less time
- For testing phases, we bring in trusted freelance QA specialists as needed
- The client communicates directly with one of the 3 developers - no account managers in the middle

**What this means for the client:**
- You get senior-level expertise on every line of code - not juniors managed by a senior
- Faster delivery because AI tools handle routine code generation, leaving developers for complex decisions
- Lower cost than a traditional agency - no overhead, no bench, no management layer
- Direct communication and accountability throughout

## 10. Risk & Change Policy

### Key Risks and How They Are Managed

| Risk | How BuildDock handles it |
|---|---|
| Razorpay API changes or delays | Tested in sandbox from Week 1; sandbox does not block development |
| WhatsApp API approval delay by Meta | Applied in Week 1; email/SMS is fallback if delayed |
| Client delays in providing credentials | Delays to credentials = delays to go-live; tracked in weekly call |
| UAT feedback requesting new features | New features are change requests, not included in this price |
| Courier API outage | Manual booking fallback is built in and tested |
| Critical post-launch bug | 3 devs available part-time for 2 months - covered in price |

### Change Request Policy

Any work not listed in Section 2 is a **change request**.

BuildDock's process:
1. Client requests change in writing (WhatsApp or email)
2. BuildDock estimates within 2-3 working days
3. Both parties agree in writing before work starts
4. Change billed at: **Rs.2,250 per developer-hour**

No informal changes. No "just a small thing" outside scope.
This protects the client from budget surprises and BuildDock from scope creep.
