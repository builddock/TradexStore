Store details

Used for storage paths and the platform subdomain. It cannot be changed later.

The default gives this client its own database, image store, search index and cache on a server that also runs other stores. Changing it later is a scheduled deployment, not a setting.

What this step decides

The store's identity, where its data lives and who receives the first invitation. The key becomes part of every storage path and the platform address, so it is permanent.

This client's data is its own. Deploying creates its own database, its own image container with its own credentials, its own search index and its own cache namespace. Nothing is shared with another client, whichever hosting option is chosen.

Nothing here is visible to other stores, and this store will never see that other stores exist.

Choose the e-commerce category

The category decides what the store can do: its product structure, how stock is identified, which features start switched on, and the words its staff and customers see. It is not a label.

Choose the site template

The template decides how the storefront looks and is laid out. It cannot change prices, stock, policies or checkout behaviour, so it can be swapped later without touching any data.

Two clients on this platform never have to look alike. More templates can be added later and assigned to categories without changing any store's data or creating a second codebase.

Branding and colours

Upload the client's logo and set the brand colours. The full colour system is derived from them and every text-on-background pair is checked for contrast before the store can be deployed.
